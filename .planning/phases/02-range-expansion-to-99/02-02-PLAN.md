<naming_and_keys_lock>

Cents-mode internal keys (the second arg to `entity_id(kind, key)`):
- Zero-deviation accidentals: bare base — `"sharp"`, `"flat"`, `"natural"`.
- Non-zero accidentals: `f"{base}{cents:+d}"`. Python's `:+d` format specifier produces `"+14"` for `14` and `"-50"` for `-50`. Examples: `"sharp+14"`, `"sharp-50"`, `"flat-7"`, `"flat+50"`, `"natural-7"`, `"natural+99"`, `"flat-99"`.
- Composite keys: same as the accidental key (one composite per accidental).
- Text keys: the literal label string — `f"{cents:+d}"` produces `"+14"`, `"-50"`, `"-7"`, `"+99"`, `"-99"`.
- Glyph keys: SMuFL glyph name verbatim — `"accidentalNatural"`, `"accidentalSharp"`, `"accidentalFlat"`. Identical to Phase 1; the same glyph entityIDs are reused across modes (only `parent_entity_id` differs by mode).
- Singleton keys (cents mode): `"12-edo"` (temperament), `"cents"` (acc system), `"cents"` (tonality). Distinct from Phase 1's `"-template"`-suffixed keys, so they live as separate entityIDs in the same `PROJECT_NAMESPACE`.

User-visible names:
- Zero-deviation accidentals: `"Sharp"`, `"Flat"`, `"Natural"` (capitalized, no cent suffix). Per FEATURES.md naming convention + D-05.
- Non-zero accidentals: `f"{Base} {cents:+d}"` where Base is `"Sharp"`, `"Flat"`, or `"Natural"`. A SPACE between Base and signed cents (different from the internal key, which has no space). Examples: `"Sharp +14"`, `"Sharp -50"`, `"Flat -7"`, `"Natural +50"`, `"Flat -99"`.
- Cent label text (TextDef.text and label_text passed to compose): `f"{cents:+d}"` — `"+14"`, `"-50"`, `"-7"` (FEATURES.md "always-signed").
- Composite names (Claude's discretion per CONTEXT.md): same convention as the accidental name. `"Sharp +14"`, `"Sharp"` (zero-dev), etc. Do NOT use Phase 1's template-specific `"New Composite"` literal in cents mode.
- Tonality system name: `"cents"` (LOCKED per TON-01).
- Temperament name: `"12-EDO"`. (User-visible name only; not part of the entityID and not externally contracted.)
- AccidentalSystem name: `"cents"`. (User-visible name; not part of the entityID.)

<sweep_ordering>
<!-- D-02 + Claude's discretion locked here. -->

Sweep iteration order (which (base, cents) pairs become Class A/B/C bundles):
- Iterate over the deterministic sequence `[(base, cents) for base in ("natural", "sharp", "flat") for cents in (0,) + tuple(c for c in range(-99, 100) if c != 0)]`. The choice of inner sequence does NOT affect output ordering of accidentals/composites in the emitted XML — those are sorted in a separate step below.
- For each (base, cents): if cents == 0 then Class A (using `build_class_a` with the cents-mode glyph); if base in ("sharp", "flat") and cents != 0 then Class B; if base == "natural" and cents != 0 then Class C.
- Strictly skip the impossible cases: there is no `Sharp +0` or `Flat -0` — the zero-dev case emits exactly 3 bundles (one per base), not 9.

Section-internal output ordering (the order of entries within each section in the emitted XML):
- `accidentalDefinitions` (D-02 + Claude's discretion): sort all 597 bundles by `pitch_delta_numerator(base, cents)` ASCENDING (-199 to +199). For pitch-delta ties, use a stable secondary sort: `(delta, base_priority, cents)` where `base_priority = {"flat": 0, "natural": 1, "sharp": 2}`. The exact tiebreak rule is not externally observable as long as it is deterministic; this rule is locked here so re-runs produce byte-identical output.
- `compositeDefinitions`: same order as `accidentalDefinitions` (Claude's discretion mirrors D-02 for ease of debugging).
- `accidentalDefinitionIDs` (the comma-space string in AccidentalSystem): same order as `accidentalDefinitions` (D-02).
- `textDefinitions`: 198 unique TextDefs (one per signed cent value -99..-1, +1..+99). Order: signed cent ascending (-99, -98, ..., -1, +1, +2, ..., +99). Per CONTEXT.md Claude's discretion.
- `glyphDefinitions`: 3 GlyphDefs. Order: natural, sharp, flat (matches the iteration order of `("natural", "sharp", "flat")`). Deterministic and stable.

Cut-out tuples (Claude's discretion per CONTEXT.md): default to `(0, 0)` for all four corners on every cents-mode accidental (including the three zero-dev entries Sharp/Flat/Natural). Phase 1's template-mode Natural carried `(0.192, 2.116)` and `(0.476, 0.512)` from the template; cents mode does NOT inherit those — they are a template quirk only.
</sweep_ordering>
