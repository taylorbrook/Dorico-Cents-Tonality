<objective>
Add a THIRD variant tonality `--mode cents-naturals-optional` that emits a
parallel `.doricolib` containing BOTH flavors of every nonzero natural ±cent
side-by-side in the same accidental system:

1. **Text-only natural ±cents** (Class C) — same visual shape as v1.0
   `cents.doricolib`'s natural ±cents (bare cent text, no glyph).
2. **♮ + cent text natural ±cents** (Class B with `allow_natural=True`) —
   same visual shape as `cents-naturals.doricolib`'s natural ±cents.

Both flavors at the same `(delta, base, cents)` produce DIFFERENT entityIDs
(distinct key suffixes) but the SAME `pitchDeltaFromNatural`. The Dorico user
picks per-note in the accidentals popover whether the ♮ glyph should display.

Zero-cent natural stays Class A (single ♮ glyph). Sharp/flat ±cents are
single Class B entries per `(base, cents)` — unchanged from both prior modes,
with their own variant-suffixed entityIDs so the third library coexists with
v1.0 cents and the 260509-e0f cents-naturals library without entityID
collision.

Purpose: Compositional flexibility. Some natural-deviation pitches read
better with an explicit ♮ glyph (visual parity with sharp/flat); others read
better without it (less staff clutter). Shipping both flavors in one library
lets the user choose per-note instead of per-library.

Output:
- New CLI mode `--mode cents-naturals-optional` (default `--out cents-naturals-optional.doricolib`)
- New tonality system display name in Dorico picker: `"cents (naturals optional)"`
- 795 accidentals (3 zero-dev + 198 sharp ±cents + 198 flat ±cents + 198 nonzero natural text-only + 198 nonzero natural with-glyph)
- 795 composites (one per accidental — composites are never shared)
- 198 dedup'd TextDefs, 3 GlyphDefs, 1 TemperamentDef (shared 12-EDO), 1 AccidentalSystem, 1 TonalitySystemDef
- **Total entity count: 1 + 1 + 1 + 795 + 198 + 3 + 795 = 1794** (matches D-09 target)
- Variant-suffixed entityIDs (`-cents-naturals-optional-textonly` vs `-cents-naturals-optional-withglyph` for the two natural flavors; `-cents-naturals-optional` for sharps/flats and zero-cent entries)
- Determinism guarantee: re-running the new mode is byte-identical
- Regression guarantee:
  - `--mode cents` produces byte-identical bytes to v1.0 `cents.doricolib` (md5 `4cd707d2f4b10154a528b95e2ff5db9f`)
  - `--mode cents-naturals` produces byte-identical bytes to shipped `cents-naturals.doricolib` (md5 `205a51d2639d6fcfd79c48b874af38e5`)

Out of scope (deferred):
- README update documenting the new mode (separate doc task post-merge).
- Shipping the `cents-naturals-optional.doricolib` artifact at the repo root.
  The orchestrator will run `python3 build.py --mode cents-naturals-optional`
  as a final step; committing the binary is a separate decision.
- Visual offset tuning for ♮+cent (reuses existing `CLASS_B_ATTACH_*` and
  `CLASS_C_TEXT_*` offsets — shared with cents/cents-naturals modes).

**Accidental display names (user-visible in Dorico's popover):**

The two natural flavors need distinct names so users can tell them apart.
Reuse the existing convention (matches v1.0 cents and 260509-e0f cents-naturals):

| Flavor                      | Display name pattern | Example     |
|-----------------------------|----------------------|-------------|
| Text-only natural +14       | `"<signed-cents>"`   | `"+14"`     |
| With-glyph natural +14      | `"Natural <signed>"` | `"Natural +14"` |

Justification: matches existing convention — v1.0 cents library uses bare
`"+14"` for its Class C natural ±cents, and 260509-e0f cents-naturals library
uses `"Natural +14"` for its Class B ♮+cent naturals. Inheriting both name
schemes makes the two flavors immediately recognizable to anyone who has
seen either prior library.

**Deterministic tiebreak between the two natural flavors at the same (delta, base, cents):**

In the sort key `(pitch_delta, base_priority, cents, variant_tiebreak)`,
the new fourth field `variant_tiebreak` distinguishes the two natural
flavors at the same `(delta=cents, base=natural, cents=cents)` triple.
Sharp/flat entries use a constant tiebreak (e.g. 0).

**LOCKED ORDER: text-only first (variant_tiebreak=0), with-glyph second
(variant_tiebreak=1)** at each cent value.

Justification: matches the v1.0 cents library's natural-±cents shape — the
text-only flavor is the "default" historical visual; placing it first
preserves locality for users migrating from cents to cents-naturals-optional
(the popover's left-to-right ordering at +14¢ shows them their familiar
"+14" entry first, then the new "Natural +14" entry as an explicit
opt-in). This ordering is purely cosmetic for picker UX — Dorico parses
each entry by entityID, not by list position.

**CLI flag value:** `--mode cents-naturals-optional` (kebab-case matches
existing `cents`, `cents-naturals`, `template`).

**Default output path:** `cents-naturals-optional.doricolib` (mirrors
`cents.doricolib` and `cents-naturals.doricolib`; sibling artifact for
ad-hoc builds).

**Why three distinct suffixes (`-cents-naturals-optional` for sharps/flats/zero-dev,
`-cents-naturals-optional-textonly`/`-cents-naturals-optional-withglyph` for nonzero naturals):**

Sharps and flats have only ONE flavor in this library (Class B, same as
cents-naturals mode), so they need only one variant suffix to disambiguate
from the cents and cents-naturals libraries. The two natural flavors need
DIFFERENT suffixes from each other (else identical entityID collision) AND
both DIFFERENT from sharp/flat (no functional necessity, but keeping suffixes
consistent within "natural ±cents at the same cent value have an `-{flavor}`
discriminator" makes the key strings self-describing under grep). Zero-cent
natural has only ONE flavor (Class A), so it shares the sharp/flat suffix.
